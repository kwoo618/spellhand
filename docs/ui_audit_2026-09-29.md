# 화면 점검 보고서 — `web/station.html` (2026-09-29)

지시: 학습자 화면 전체 + 교사 모드 화면을 실제 브라우저 창에서 보고, 세 등급으로 나눈다.
[분명함] 만 고치고 [판단 필요] 는 권고만 남긴다. 사용자가 자리에 없어 묻지 않고 판단했다 —
판단 근거를 항목마다 적는다.

## 어떻게 봤는가

- 서버: `DEVICE_MODE=mock`, **스크래치 DB**(scratchpad 의 `audit.db`), LLM 없음(`build_station(llm=None)`
  → 규칙 폴백). `station.db` 는 열지도 않았다. Anthropic API 호출 없음.
- 브라우저: Chrome 의 **최상위 탭**(iframe 아님). 뷰포트를 JS 로 재서 1280×800, 1920×1080 을 확인하고 찍었다.
  창 오른쪽 스크롤바가 실제로 보이는 상태다.
- **한계 — 솔직히 적는다.** 1920×1080 에서는 스크린샷 도구가 여러 번 시간 초과로 실패했고, 성공한
  것도 캡처 영역이 뷰포트 일부(1456×819)였다. 그래서 1920 에서는 JS 로 배치를 쟀다(가로 넘침 없음,
  교사 격자 1248px 가운데 정렬, 로그 패널 폭 637px). 눈으로 본 것은 1280×800 이 중심이다.
- 거친 흐름: 홈 → 글자(공부 시작 → [보기] → 표현 중 어두운 화면 → 돌아옴) → 훈련(버튼 입력, 시작 →
  표현 중 → 답할 차례 → 두 번 틀림 → 결과) → 요약 → 내 진행 → 교사 모드(계획 · 로그: 계획 생성 →
  승인 대기 → 승인 → 락이 물린 채 다시 승인 → 거부 문구·손 놓기 두 번 누르기 / 혼동 행렬: 판별·단어·
  새로고침). MCP 로그에는 `POST /api/mcp-log` 로 `tool_call` · `blocked` · `tool_result` 를 한 건씩 넣어
  줄 모양을 봤다.

## 애니메이션 — 어디에만 허용하는가

지시의 규칙을 그대로 옮긴다. 테스트와 DECISIONS §59 에 적는다.

- 허용: **홈 화면**의 등장(페이드 + 8px 올라옴, 0.3초 이하, 한 번), 홈 메뉴 행의 누름·올림(0.15초).
- 금지: `data-phase="moving"` 인 패널이 보이는 동안 **어느 화면에서든** — 훈련 중에 홈 탭으로 가도 손은
  움직이고 있을 수 있으므로 전역으로 끈다. 훈련 화면(`#trainView`) · 글자 화면(`#studyView`) 전체.
